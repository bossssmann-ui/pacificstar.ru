# PS-11 — Инвентаризация языковых URL и редакционных пробелов

Инвентаризация локализации на текущей ревизии. Только фиксация состояния; переводы текстов статей и RSS отложены (PS-16C), сам перевод контента — редакционная задача.

## 1. Схема языковых URL

- **Один физический URL на страницу.** Отдельных языковых директорий/файлов нет (`/en`, `/zh`, … отсутствуют).
- Язык переключается **клиентски**: `data-i18n` + словари `locales/*.json`, скрипт `js/i18n.js`.
- Порядок определения языка (`getLang`): `?lang=` в URL → `localStorage['ps-lang']` → язык браузера (кроме en) → `ru` по умолчанию.
- **hreflang-альтернативы** во всех основных страницах: `ru` (канонический), `en/zh/ja/ko` через `?lang=xx`, `x-default` = ru. Пример: `https://pacificstar.ru/ved.html?lang=en`.
- `i18n.js` **читает `?lang=`** (URLSearchParams) и синхронизирует его в URL при переключении — hreflang-ссылки функциональны.
- `<html lang="ru">` фиксирован (не меняется при переключении — кандидат на улучшение: обновлять `lang` динамически).

**Ограничение (SEO):** перевод применяется на клиенте (JS). Краулеры без исполнения JS на `?lang=en` видят русский дефолт. Серверного рендера переводов нет. Для полноценной языковой индексации потребовалась бы серверная отдача или пререндер (вне текущего стека; отдельное решение).

## 3. Редакционные пробелы

1. **ja/ko — 564 непокрытых ключа.** Элементы с этими ключами у ja/ko-пользователей показывают **русский дефолт из HTML** (фолбэк i18n). Затрагивает крупные блоки (напр. `about.*`, множество `*.p.*`). → нужен перевод/дозаполнение ja/ko.
2. **Непереведённые (английские) значения в неанглийских локалях.** Часть значений в ja/ko/zh фактически на английском (напр. `index.process.step2.desc` = «Our manager calculates…» в ja/ko). → редакционная вычитка на «английские остатки».
3. **Meta-ключи рассинхронизированы.** `meta.*.title` / `meta.*.desc` (12 ключей: index/about/services/contacts/account/remote_regions) есть в `en/zh/ja/ko`, но **отсутствуют в `ru`**. → привести к единому набору: либо добавить ru-мета-ключи, либо убрать лишние.
4. **`<html lang>` статичен** (`ru`) независимо от выбранного языка — минорный a11y/SEO дефект.
5. **Порядок «сначала формы/аналитика/новости, потом переводы».** Перевод текстов статей и RSS отложены (PS-16C); данный документ — только инвентаризация, не перевод.

## 4. Что НЕ делаем сейчас
- Не переводим контент и не редактируем тексты статей (редакционная задача + ревью Романа).
- Не меняем стек на серверный рендер языков.
- Не удаляем «лишние» meta-ключи без согласования единого набора.

**Дальше:** согласовать целевой объём локализации (полные ja/ko или приоритетные страницы), единый набор meta-ключей, динамический `<html lang>`. Перевод — редакционно, отдельными PR.
