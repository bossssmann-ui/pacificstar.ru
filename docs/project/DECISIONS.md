# Pacific Star — DECISIONS

Принятые решения и их основания. Дополнять по мере работы.

## PS-00 (7 сентября 2026)

1. **Трекинг задач в репозитории, а не в GitHub Issues.** Основание: в среде Cloud Agent нет доступа на запись к Issues (`gh` только на чтение). Задачи PS-XX ведутся в `docs/project/PLAN.md` со стабильными идентификаторами. При появлении доступа — синхронизировать с Issues без дублей.
2. **Агент не выполняет merge.** Основание: merge в `main` автоматически публикует сайт (релиз), а политика среды запрещает автоматический merge без явного указания. PR оставляется владельцу на ревью и merge. Это не отменяет остальной цикл работы.
3. **Внутренняя документация исключена из публикации.** Основание: деплойный `rsync` не исключал `docs/` и `.cursor/`, из-за чего внутренние файлы попали бы на сайт. Добавлены `--exclude='docs/'` и `--exclude='.cursor/'` в `tilda-deploy.yml`. Это обоснованное изменение деплоя, не PR-гейта, и не ослабляет проверки.
4. **«Три проверки» не подтверждены — не выдумываем названия.** Основание: на реальных PR присутствует только `GitGuardian Security Checks`; защита ветки недоступна токену (403), rulesets пусты. Зафиксировано в `CI-CONTRACT.md` как блокировка; запрошены точные названия и/или доступ.
5. **Правило Cursor добавлено, существующие инструкции не перезаписаны.** Основание: раздел 2 плана. `.cursor/rules/pacificstar-workflow.mdc` ссылается на `docs/project/*` и `.github/copilot-instructions.md`, не дублируя их.
6. **Стек не переписываем.** Основание: раздел 3 плана и `.github/copilot-instructions.md` — vanilla HTML/CSS/ES5-JS без фреймворков и сборки.

## Уточнение PS-00 (7 сентября 2026)

7. **Отчёты сессий — скачиваемым артефактом, не в репозитории.** Основание: замечание владельца; отчёт нужно забирать из UI и передавать шефу. Правило обновлено; файл-отчёт удалён из `docs/`.
8. **Секрет в `.env` — untrack без переписывания истории (PR #246).** Основание: репозиторий публичный, `.env` отслеживался с `TELEGRAM_BOT_TOKEN`. Рабочая копия сохранена, история не трогается (регламент). Ротация токена — обязательное действие владельца; значение остаётся в истории.
9. **Сборку окружения с секретом не сохранять.** Основание: снапшот `#244` снят с checkout `main`, содержащего `.env`. После merge `#246` — чистая пересборка; текущую сборку для будущих агентов не использовать.
10. **Merge заблокирован до контракта проверок.** Основание: раздел 3 плана — при неизвестном контракте merge последовательность останавливается. Полномочие на самостоятельный merge не отменяет требование реально установленных проверок.
11. **Диагноз доступа зафиксирован фактами** (push/PR доступны; Issues-write и `administration:read` — нет). См. `CI-CONTRACT.md`. Не обходить ограничения среды.

## Согласование владельца (8 сентября 2026)

12. **Контракт проверок утверждён**: `GitGuardian Security Checks` + `PHP lint` + `HTML validation`; все три обязаны успешно пройти на актуальной ревизии PR (report-only/skipped/neutral/missing/успех прошлого коммита не в счёт). Историческую «тройку» больше не ищем.
13. **Merge — вручную владельцем** (временно). Агент не мёржит и не обходит ограничения среды (PAT и пр.). После merge — проверка публикации и продолжение.
14. **Учёт задач — в `PLAN.md`** (временно, Issues недоступны).
15. **CI внедряется отдельным PR** (`ci.yml` + реальные исправления HTML), не смешивая с редизайном/коммерческим контентом. HTML-нарушения исправляются по существу, без массового отключения правил и исключения страниц.
16. **Telegram-секрет**: статус «потенциально действующий опубликованный секрет; действительность не проверялась; отзыв отложен владельцем». Не считать устранённым; сборку с секретом не сохранять.
